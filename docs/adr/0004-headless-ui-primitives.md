# ADR-0004：无头原语 + 自有设计令牌，不用成品 UI 库

- 状态：已接受
- 日期：2026-10-14
- 相关：[界面架构](../UI_ARCHITECTURE.md) §7、§11

## 背景

目标是 Apple 风格的观感，同时要开源分发（Windows/macOS，将来可能移动）。两条约束同时成立：

1. **成品 UI 库的默认视觉与企业后台风格**（Material、Ant Design）与目标观感差距大，改造成本高于自建。
2. **字体与图标有许可证限制**。SF Pro 与 SF Symbols 的许可仅覆盖 Apple 平台上的 Apple 平台软件，不能打包进面向 Windows 的开源安装包。

当前 `src/ui/styles.css` 是 16KB 单文件，`:root` 有 12 个变量但大量取值硬编码，`border-radius` 有 11 种不同数值。

## 决策

- **行为与可访问性**用无头原语：`radix-ui`（已合并为单一包，MIT）。
- **样式**用自有 CSS 变量令牌 + 组件样式，不引入 Tailwind，不引入带默认皮肤的组件库。
- **图标**用 Lucide（ISC），不使用 SF Symbols。
- **字体**用可嵌入的开源字体（Inter，SIL OFL）自托管，或退回系统字体栈；**不打包 SF Pro**。
- **动效**克制使用，尊重 `prefers-reduced-motion`。

## 后果

**正面**

- 视觉完全可控，能做到接近 macOS 的质感而不与某个库的皮肤对抗。
- **许可证干净**，可合法分发到 Windows 与 Linux。
- 无头原语解决了最费时的部分：焦点陷阱、Esc 关闭、ARIA 属性、键盘导航、滚动锁定、`data-state` 动画钩子。这些自己写正确率很低。
- 依赖体积小，原语按需引入。

**负面**

- **要自己写样式**。这是真实的工作量，也是本项目最耗时的部分之一。没有"装上就有整套组件"的捷径。
- 需要自己维护令牌体系，容易出现不一致（现状 11 种圆角就是先例）。
- 无头库的 API 是组合式的（`Dialog.Root/Trigger/Portal/Content`），比成品库啰嗦。
- `radix-ui` 在 2026 年 7 月合并了包结构，旧文档与教程仍大量使用逐组件包名，检索时容易困惑。

## 被否掉的方案

- **shadcn/ui**：本质是"复制 Radix + Tailwind 样式的源码"，观感方向接近但默认皮肤偏中性，仍需大量调整；且它把 Tailwind 一起带进来，与"自有 CSS 令牌"路线冲突。2026 年 7 月起其新项目默认基于 Base UI 而非 Radix，跟随它会把项目绑到一个仍在变动的上游选择上。
- **Material UI / Ant Design / Chakra**：默认皮肤与目标观感差距大，改造成本高于自建。
- **Base UI / React Aria Components**：都是合理选项，但 Radix 的文档与示例最丰富、下载量与维护度最高，对单人项目更省时间。
- **直接打包 SF Pro**：违反 Apple 字体许可。
- **引入 Tailwind**：不是错误选择，但会与既有 CSS 变量体系并存，短期内两套样式来源反而更乱。若将来统一切换，应作为独立 ADR。

## 重新考虑的条件

- 自建组件的维护成本成为主要开发瓶颈（例如每月都在修同一类样式问题）。
- 需要支持 RTL 或多语言排版，而自有令牌体系无法承载。
- 无头原语的上游停止维护，或包结构再次剧变导致升级成本过高。
