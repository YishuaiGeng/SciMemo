# ADR-0007：延后原生移动端，先做可安装 PWA

- 状态：已接受
- 日期：2026-10-14
- 相关：[平台能力矩阵](../PLATFORM_MATRIX.md)、[ROADMAP](../ROADMAP.md) M3、[ADR-0003](0003-manual-sync-no-crdt.md)

## 背景

`package.json` 已有 `android:dev` / `ios:dev` 脚本，`tauri.conf.json` 也配置了移动入口，但 `src-tauri/gen/` 不存在——**移动目标从未初始化**。Rust 工具链也从未编译过。

同时，决定"手机能不能用"的不是外壳，而是数据流：

- 同步是**手动**的，需要用户填写服务地址和令牌，令牌**只驻留设置页内存**，每次重启要重输（`Settings.tsx`、`PLATFORM_MATRIX` §2）。
- 该令牌是**单工作区共享令牌**，无法按设备撤销（`SM-102` 未实现）。

而且手机端的数据可靠性有硬限制：iOS 会清理长期未访问站点的存储；Android 系统也可能回收。桌面端才是唯一可靠的权威副本。

## 决策

**不在 M1/M2 投入原生移动端。** 手机需求先用**可安装 PWA** 验证：

1. 加 `manifest.webmanifest` + `apple-touch-icon` + `theme-color`，支持"添加到主屏幕"。
2. 新增 375px 优先的**快速捕获**页（一句话 → note 或 deadline），与一个只读的"近期日程"。
3. 系统通知**不做**；应用内列表已足够，见 [平台能力矩阵](../PLATFORM_MATRIX.md) §4。
4. 资源必须本地打包：`tauri.conf.json` 的 CSP 是 `default-src 'self'`，PWA 清单与图标不能引外部来源。

**门禁条件**：满足全部三条后再考虑原生。

- `SM-102` 设备级令牌与撤销已完成；
- 同步不再需要每次手动输入凭据；
- 有**真实使用证据**——连续两个月在手机上实际打开过 SciMemo。

真做时**先只做 Android**：可侧载、免开发者账号年费、迭代快。iOS 的签名与审核成本最后付。

## 后果

**正面**

- 零新增原生工具链，不引入 Rust 移动构建、Xcode、Android SDK/NDK 的持续维护负担。
- 用最低成本检验需求真伪。如果六个月后手机端从没被打开过，就省下了一条产品线的开发与维护。
- PWA 与桌面共用同一份前端代码与读模型，不存在第二套实现。
- 不承诺系统通知，就不必面对"权限被拒后功能不可用"的设计问题。

**负面**

- PWA 在 iOS 上的体验确实弱于原生：无后台通知、存储可能被清理、无法进入分享面板、启动速度略慢。
- **手机上不能作为唯一副本**，用户必须理解这一点。这是设计前提而非可修的缺陷。
- 如果最终仍要做原生，PWA 阶段的部分工作（快速捕获页的布局）可复用，但原生壳与凭据存储要重做。
- "已支持手机"这件事被明确延后，README 与文档必须如实说明（当前 `README.md` 已注明移动壳"已提供，尚未编译／签名／真机验收"）。

## 被否掉的方案

- **同一轮同时做三端**：在核心数据可靠性（`SM-002`/`SM-004`）尚未验证时，把风险乘以三。且手机端的真实需求尚未被观察。
- **不做手机，只做桌面**：可能错过"随手记录"这一最有价值的场景——科研灵感常常出现在离开电脑时。PWA 以极小代价保留了这个可能。
- **先做 iOS**：需要 99 美元/年的开发者账号与审核流程，而 Android 的侧载与分享面板更适合早期迭代。
- **做微信小程序 / 网页快捷方式**：前者引入平台绑定与审核，后者不解决全屏与图标问题。

## 重新考虑的条件

- 门禁条件全部满足。
- 或出现 PWA 无法解决的具体阻塞（例如必须在分享面板出现、必须后台接收通知、必须与系统日历双向同步）。
- 或 iOS 的存储清理在实践中导致数据丢失投诉（届时应先解决"手机不是权威副本"的提示与同步可靠性，而不是直接上原生）。
